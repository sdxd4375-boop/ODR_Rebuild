## 0. 一句话结论

**内核（研究图）与路线图的"可造性"是高的（约 8/10），但"当前工作区作为一个可交接、可复现的工程产物"，可造性只有约 3/10。**

设计已成型、计划也已细化到代码级，但项目还没有被"打包成工程"：**164 个未跟踪文件 + 1135 行未提交修改**（整个魔改层不在版本控制里）、**一个损坏到无法 import 核心包的 venv**、**一条必然失败的冷启动链路**，以及**约 20 个决定成败的配置项没有任何文档**。

最大风险不是技术难点，而是：**现在换一台机器 clone 这个仓库，你得到的只有 upstream，拿不到这个项目。**

## 4. P2 · 安全与合规 —— **现有计划的最大盲区**

计划 G1–G12 与 P0–P5 中**没有任何安全任务**。以下四项建议作为 P0.5 插入。

### S1 图表沙箱可绕过，等于把模型生成代码当可执行代码跑（高）

```python
# sandbox.py:35-44
for node in ast.walk(tree):
    if isinstance(node, ast.Import): ...
    elif isinstance(node, ast.ImportFrom): ...
```

- 只检查 `Import` / `ImportFrom` 节点。**`__import__("os").system(...)`、`eval(...)`、`exec(...)` 全部通过检查**（它们是 `Call`，不是 `Import`）。
- `trusted_preamble`（`sandbox.py:113-118`）直接拼在用户代码前执行，无白名单约束。
- `subprocess.run([sys.executable, "-I", script])` 无内存/CPU 限制、无 `--network none`；`sandbox.py:6-7` 的注释自认"生产应放进容器"，但**这条从未落地**。
- 攻击链是现实的：研究过程会抓取任意网页 → 网页里的 prompt injection 进入报告 → `charts.py` 的 LLM 提示要求按报告内容写 matplotlib 代码 → 在服务进程同一 OS 用户下执行。多用户部署下这是 RCE。

**建议：** ① 白名单改"只允许显式列出的 `import` 且禁止 `__import__/eval/exec/compile/globals/getattr` 等危险 builtins 引用"（AST 层禁 `Call.func` 为这些名字）；② 子进程加 `resource` 限额；③ 容器化后加 `--network none`；④ 至少把出图从 API 进程彻底隔离（队列 + worker）。

### S2 无 SSRF 防护 / 无出网白名单（中）

`utils.py:274` 用 `aiohttp.ClientSession` 抓取搜索返回的任意 URL，无内网地址过滤（`127.0.0.1`、`169.254.169.254`、RFC1918 均可达）。自建服务部署在内网时是高价值目标。计划未覆盖。

### S3 无速率限制 / 无配额（中）

全仓无限流中间件；`AUTH_MODE=supabase` 时**没有任何成本闸**（`apply_cost_caps` 只在 local 生效）→ 一个已注册用户可无限调用。P3-3.4 只做"报表"，建议同时做"闸"（per-user 日/月 token 上限，命中即 429）。

### S4 数据治理与"私有"承诺不符（中）

- 无报告删除/导出接口，无保留期策略。
- `EMBEDDING_MODEL` 默认 `openai:text-embedding-3-small` → **上传的私有文档正文会发到 OpenAI 云端**；这与"私有语料"的对外表述冲突，直到 P1-1.3 提供本地 embedding 才缓解。建议在 P1 之前，先在 UI/README 明示数据流向，并给一个"仅本地 embedding"开关。
- `.env` 内含真实 DashScope key（`sk-ws-...`，`.env:9`）。已核实**未进 git**（`git check-ignore -v .env` → `.gitignore:32`），但工作区一旦打包分享即泄漏。**建议立即轮换该 key**，并把"密钥轮换"写进交接清单。

### S5 可观测性（低，但排障必需）

`health.py:13-18` 恒 200 且恒 `status:"ok"`（即使 db/graph 都是 false）。`.env` 里 `LANGSMITH_TRACING=false`（重复出现两次，`:7` 与 `:23`，后者覆盖）→ 出问题时既无 trace 也无分项诊断。建议：health 按分项返回 503/200；加 `/api/metrics`；开 `python-json-logger` 或至少给每个 run 打 `thread_id` 关联日志。
